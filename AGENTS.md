## 1. Project Overview

This repository and workspace maintain a customized build of **Chatterino 2** — the high-performance desktop chat client for Twitch, Kick, and IRC — featuring a full native **Russian UI localization subsystem** and dynamic language switching.

### Key Characteristics
- **C++ Standard:** C++20 / C++23.
- **GUI Framework:** Qt 6.8+ (Widgets, Core, Gui, Network, Svg, LinguistTools).
- **Build System:** CMake + Conan + MSVC 2022.
- **Packaging:** Portable Windows distribution with embedded Qt runtime and crashpad support.
- **CI/CD:** Automated cloud builds and release packaging via GitHub Actions (`.github/workflows/build.yml`).

## 3. Localization Architecture (`I18n`)

### 3.1 Components
1. **`chatterino::I18n` Singleton (`src/util/I18n.hpp`, `src/util/I18n.cpp`):**
   - Manages the lifecycle of `QTranslator appTranslator_` and `QTranslator qtTranslator_`.
   - `loadLanguage(const QString &langCode)`:
     - When `langCode == "ru"`: Loads `:/translations/chatterino_ru.qm` from Qt embedded resources and installs it via `QCoreApplication::installTranslator(...)`. Also installs standard Qt translations (`qt_ru`) for system dialog buttons (*ОК*, *Отмена*, *Да*, *Нет*).
     - When `langCode == "en"`: Removes any active translators, reverting cleanly to default English strings.
     - **Fail-safe guarantee:** If `.qm` is missing or corrupted, the application logs a warning and continues in English without throwing or crashing.
2. **Settings Integration (`src/singletons/Settings.hpp`):**
   - `QStringSetting uiLanguage = {"/general/uiLanguage", "ru"};`
   - In `Application::initialize`, language is loaded from `settings.uiLanguage.getValue()`.
   - A reactive connection (`settings.uiLanguage.connect(...)`) automatically reloads the translator when the user changes the setting.
3. **UI Setting (`src/widgets/settingspages/GeneralPage.cpp`):**
   - Under General settings, a dropdown provides `Русский` (`"ru"`) and `English` (`"en"`).

## 4. How to Add or Edit Translations

### 4.1 Step 1: Mark Strings in C++ Code
Wrap any user-visible English text with the Qt translation macro:
```cpp
// In QObject-derived classes (widgets, dialogs):
tr("Your English String Here")

// In non-QObject contexts or static functions:
QCoreApplication::translate("ContextName", "Your English String Here")
```

### 4.2 Step 2: Add Entry to `chatterino_ru.ts`
Open `chatterino2-source/resources/translations/chatterino_ru.ts` and add a `<message>` block under the appropriate `<context>`:
```xml
<context>
    <name>ContextName</name>
    <message>
        <source>Your English String Here</source>
        <translation>Ваш русский перевод</translation>
    </message>
</context>
```

### 4.3 Step 3: Recompile `.ts` to `.qm`
Run `lrelease` using Python or Qt tools:
```powershell
& "C:\Users\LOYOL\AppData\Local\Programs\Python\Python313\Lib\site-packages\PySide6\lrelease.exe" `
    "resources\translations\chatterino_ru.ts" `
    -qm "resources\translations\chatterino_ru.qm"
```
Because `resources/translations/chatterino_ru.qm` is automatically globbed by `cmake/resources/generate_resources.cmake`, it is immediately bundled into the internal Qt resource system at `:/translations/chatterino_ru.qm`.

## 5. Build & CI/CD Workflow

All binary builds are compiled in the cloud using **GitHub Actions** on `windows-latest` runners to avoid large local build overhead (~30 GB dependencies).

### 5.1 Push & Trigger Build
```powershell
cd "chatterino2-source"
git add .
git commit -m "feat(i18n): update translations"
git push origin feat/russian-localization
```

### 5.2 Monitor GitHub Actions Run
- Track CI workflow: [LoyoL99/chatterino2 Actions](https://github.com/LoyoL99/chatterino2/actions)
- Build time for Windows x64: ~10–15 minutes.
- Artifact produced: `chatterino-windows-x86-64-Qt-6.8.3.zip`.

### 5.3 Deployment Protocol
1. Download the artifact `.zip` from GitHub Actions API or web interface.
2. Ensure Chatterino is closed (`Stop-Process -Name chatterino -Force`).
3. Make an automatic backup of the existing executable:
   ```powershell
   Copy-Item ".\chatterino.exe" -Destination ".\chatterino.exe.bak" -Force
   ```
4. Extract and copy the new `chatterino.exe` into `Chatterino2\`.
5. Relaunch:
   ```powershell
   Start-Process "..\..\ChatterinoWithPoints.bat"
   # or
   Start-Process ".\chatterino.exe"
   ```

## 6. Agent Rules & Guardrails

When working on this codebase, all automated agents must strictly follow these rules:

1. **Never Break Fallbacks:** Never hardcode translated strings directly into core C++ logic where an English identifier or setting key is expected. Always use `tr(...)` or `chatterino::I18n`.
2. **Preserve User Data:** Never touch or clear files in `%APPDATA%\Chatterino2\` unless explicitly requested by the user. User tokens, IRC accounts, split configurations, and Twitch auth must remain intact.
3. **Backup Before In-Place Modification:** Always verify that `chatterino.exe.bak` is created before replacing `chatterino.exe`.
4. **Clean Git Practices:** All code changes must be committed cleanly to branch `feat/russian-localization` with descriptive conventional commit messages (`feat(i18n): ...`, `fix(ui): ...`, `build(cmake): ...`).
5. **No Token Leaks:** Never persist personal access tokens (PAT) in git remotes or plain-text commit history. Reset remote URLs to standard HTTPS after push operations.
